Minidoracat MiniMap - guide to Zomboid/Lua/MinidoracatMiniMap (format v1)

This file is generated by the mod only when it is missing; it is never overwritten
afterwards, so feel free to add your own notes. Deleting it does not affect the mod
(it comes back on the next startup).
A Traditional Chinese version of this guide sits next to it as _README_CH.txt.
The full contract, including every edge case, lives in the mod source headers:
  42/media/lua/server/MinidoracatMiniMapPlayerExport.lua
  42/media/lua/shared/MinidoracatMiniMapPOIExport.lua

== What is in this folder ==

  poi_blocks.json           Built-in resource point (POI) blocks. Written once per
                            startup; tied to the mod version, not to a save.
  players_SAVENAME.json     Player positions. Only created when the sandbox option
                            "Export player position file" is enabled, then rewritten
                            every N seconds (sandbox, default 5).
                            SAVENAME = server name (MP) or save folder name (SP).
  _README_CH.txt            This guide (Traditional Chinese).
  _README_EN.txt            This guide (English).

  The Zones addon writes zones.json (server-defined areas) into the sibling folder
  MinidoracatMiniMapZones/ - that is a different mod's output.

== Fields of players_SAVENAME.json ==

The first line is metadata, then one line per player, then a final ]} terminator.

  v                 Format version, currently 1.
  modversion        Mod version installed when the file was written.
  save              Save name. Must equal the save folder you are about to touch.
  ts                Write time (real-time epoch milliseconds). Freshness comes from this.
  interval          Export period in effect at write time (seconds, 1-300).
  offlineAuthority  Always "observed-subset". Any other value means the semantics
                    changed - abort.
  offlineIncluded   Whether the sandbox asked for offline entries. false means there
                    are none in the file; it does NOT mean there are no offline
                    characters.
  offlineSince      Start of the offline history (epoch ms). Characters who logged
                    out before this are not in the list. It carries across restarts,
                    and resets to "now" when read-back fails or when the export was
                    turned off and back on.
  offlineTruncated  Whether the offline list ever had its oldest entries dropped due
                    to the entry cap (2000).
  online            Number of entries with online:true.
  count             Total number of entries in players.
  players           Array of entries:
                      name    Account username. Use this to kick.
                      idx     Split-screen slot (0-3).
                      steamId Steam64 as a 17-digit string. Empty when unavailable:
                              a non-Steam server, or that player's client has not
                              reported yet. See "About steamId" below for how far
                              you may trust it.
                      online  Whether the player is online at this moment.
                      x, y    World position in whole tiles. Save chunk = floor(x/8).
                      z       Floor; basements are negative.
                      seen    When this position was observed (epoch ms).

  The unique key is (name, idx), not name: one account can have several characters
  in different places via local split screen. De-duplicating by name alone silently
  discards a real player's position.

== The one thing that matters most: the two kinds of entries differ ==

  online:true entries are complete.
    They come from the engine's authoritative online list, covering every
    split-screen slot of every connection.
    You may conclude: "no online player is standing on this land right now".
    If any online player's name cannot be written losslessly, or a duplicate
    (name, idx) shows up, the mod skips the whole round and writes nothing, so the
    file goes stale and your freshness check stops you. It never quietly omits a
    player.

  online:false entries are only the subset this mod observed, and are never complete.
    At least four groups are missing: characters who logged out before the mod
    started recording, everyone (when the sandbox disables offline entries), entries
    dropped by the cap, and players who moved and logged out after the last
    observation.
    You may conclude: "someone listed IS standing on this land" (positive evidence).
    You may never conclude: "nothing is listed here, therefore no offline character
    is here".

  To prove that a piece of land holds no character at all, the only authoritative
  source is the save's players.db (networkPlayers table; the engine stores the
  current position when a player disconnects). That is SQLite and the game's Lua
  cannot read it - only an external tool while the server is stopped. The files in
  this folder are live information for a running server (who is where, who to kick),
  not a complete post-shutdown census.

== About steamId (client-reported, consistency-checked) ==

This field is not computed by the server. The player's client reports it and the
server keeps it only after a consistency check. The reason is that the engine gives
the server no way to obtain an exact Steam64: the server only sees the Java long
after conversion to a Lua float, and at Steam64 magnitude (~7.66e16) the float step
is 16, so the last digit or two are silently rounded away. Every engine function
that stringifies a SteamID is client-side only.

The server applies two checks: format (17 digits, not below the start of Steam's
individual-account range), and a comparison of the reported value against the
server's own float. Arbitrary values are rejected, but a single float corresponds to
roughly 15-16 adjacent Steam64 values, and most of those are real accounts too, so a
malicious client can still pick one of them and pass the check.

So: use it for human-readable cross-referencing, audit logs, or tracking players
across renames. Do NOT use it for authorization, bans, or ownership decisions. If you
need an authoritative value, read the networkPlayers table in the save's players.db
after the server has stopped - the steamid column there is written by the server.

== If you are writing an external tool, do these ==

  1. Parse the whole file strictly. On any parse error, treat the file as absent and
     abort destructive work - the outer object only closes at EOF, so a truncated
     file can never pass strict parsing. Do not stream it line by line.
  2. players length must equal count, and the number of online:true entries must
     equal online. De-duplicate by (name, idx); if a duplicate appears, abort the
     whole document instead of silently de-duplicating.
  3. Freshness, fail-closed: if now - ts exceeds a few times interval (3x is a good
     default), the export has stopped (sandbox off, mod removed, server down, or the
     mod refused to write), and online only reflects the server's last moment. Also
     abort when ts is in the future beyond a small clock skew (~60s), otherwise a
     future timestamp makes a stale file look fresh forever. interval outside 1-300
     means the file is untrustworthy.
  4. save must equal the save folder you are operating on, and offlineAuthority must
     be "observed-subset".
  5. The offline list cannot prove absence (see above). A very recent offlineSince,
     or offlineTruncated being true, means the offline history is even less
     complete - be more conservative with destructive work.
  6. Tolerate the file being absent (the feature is off by default, or the first
     period has not elapsed yet).

== Privacy ==

Enabling "Export player position file" writes player positions to disk. Turn it on
only when the server is actually paired with such a tool; ordinary servers do not
need it.
