Minidoracat MiniMap - Zomboid/Lua/MinidoracatMiniMap ディレクトリ説明（format v1）

本ファイルは存在しないときだけ MOD が自動生成し、その後は一切上書きしません
（自由にメモを追記できます）。削除しても MOD の動作に影響はなく、次回起動時に
再生成されます。
繁体字中国語版と英語版が同じディレクトリにあります：_README_CH.txt、_README_EN.txt。
完全な契約（全エッジケース含む）は MOD ソースのファイルヘッダにあります：
  42/media/lua/server/MinidoracatMiniMapPlayerExport.lua
  42/media/lua/shared/MinidoracatMiniMapPOIExport.lua

== このディレクトリにあるもの ==

  poi_blocks.json           内蔵資源ポイント（POI）ブロック。起動ごとに 1 回書き
                            出し、内容は MOD バージョンに紐づき、セーブとは無関係。
                            選択フィールド "u":1 ＝地下施設（B42 basement、カテゴリ
                            部屋の主フロアが地下）。additive 拡張——ツール側は
                            未知キーを無視すれば OK。
  players_セーブ名.json     プレイヤー座標。サンドボックスで「プレイヤー座標
                            ファイルの出力」を有効にしたときだけ生成され、以後
                            N 秒ごと（サンドボックスで調整可、既定 5）に全体を
                            書き直します。セーブ名＝マルチのサーバー名／シングル
                            のセーブフォルダ名。
  _README_CH.txt            本ファイル（繁体字中国語）。
  _README_EN.txt            本ファイル（English）。
  _README_JP.txt            本ファイル（日本語）。

  なお Zones addon は隣のディレクトリ MinidoracatMiniMapZones/ に zones.json
  （サーバー定義ゾーン）を書きます。あれは別 MOD の出力です。

== players_セーブ名.json のフィールド ==

1 行目が metadata、以降 1 プレイヤー 1 行、最終行の ]} で閉じます。

  v                 フォーマットバージョン。現在は 1。
  modversion        書き出し時にインストールされていた MOD バージョン。
  save              セーブ名。操作対象のセーブディレクトリ名と一致しない場合は
                    このファイルを使わないでください。
  ts                書き出し時刻（実時間 epoch ミリ秒）。鮮度判定はこれで。
  interval          その時点で有効だった出力周期（秒、1-300）。
  offlineAuthority  固定 "observed-subset"。別の値を読んだら意味が変わって
                    いるので中止してください。
  offlineIncluded   サンドボックスがオフライン行の出力を要求しているか。
                    false＝オフライン行ゼロ。「オフラインキャラがいない」という
                    意味ではありません。
  offlineSince      オフライン履歴の起点（epoch ミリ秒）。これより前にログアウト
                    したキャラはリストにいません。再起動をまたいで継続；読み戻し
                    失敗、出力を無効化→再有効化、またはファイルにオフライン行が
                    ない場合は現在時刻にリセットされます。
  offlineTruncated  オフラインリストが上限（2000 件）で最古から切り捨てられた
                    ことがあるか。
  online            リスト中 online:true の件数。
  count             players の総件数。
  players           プレイヤー配列。各行：
                      name    アカウント名（username）。キックはこれで。
                      idx     分割画面スロット（0-3）。
                      steamId Steam64（17 桁文字列）。取得できない場合は空文字列
                              ——非 Steam サーバー、またはそのプレイヤーの
                              クライアントが未報告。信頼度は下記「steamId に
                              ついて」参照。
                      online  この瞬間オンラインか。
                      x, y    世界座標（整数マス）。セーブ chunk ＝ floor(x/8)。
                      z       階層。地下は負数。
                      seen    この座標を観測した時刻（epoch ミリ秒）。

  一意キーは (name, idx) であって name ではありません：同一アカウントが同じ PC の
  分割画面で複数キャラを別々の場所に立たせられます。name だけで重複排除すると
  実在プレイヤーの座標を捨てることになります。(name, idx) の重複が出たらファイル
  自体が信頼できないので、黙って重複排除せず文書全体を破棄してください。

== 最重要：2 種類の行は証明力が違う ==

  online:true の行は完全です。
    ソースはエンジンの権威オンラインリストで、全接続の全分割画面スロットを走査。
    「この瞬間、この土地にオンラインプレイヤーはいない」という結論に使えます。
    オンラインプレイヤーの名前が無損失で書けない、または (name, idx) 重複がある
    場合、本 MOD はそのサイクル全体を書き出しません——ts の期限切れであなたの
    ツールに止めさせます。黙って 1 人減らすことは絶対にしません。

  online:false の行は「本 MOD が観測できたサブセット」に過ぎず、常に不完全です。
    少なくとも 4 種類が欠けます：本 MOD が記録を始める前にログアウトした人、
    サンドボックスでオフライン出力が無効だった期間の全員、上限で切り捨てられた
    人、最終観測後に移動してからログアウトした人。
    使える結論は「リストにいる人はこの土地にいる」（正の証拠）だけ。
    「リストにいないから、この土地にオフラインキャラはいない」とは絶対に
    言えません。

  ある土地に「キャラが一人もいない」ことを証明できる唯一の権威ソースはセーブ内の
  players.db（networkPlayers テーブル、切断時にエンジンが座標を書き込む）です。
  あれは SQLite でゲームの Lua からは読めず、停止中の外部ツールだけが読めます。
  このディレクトリのファイルは「サーバー稼働中のリアルタイム情報」（今誰がどこに
  いるか、誰をキックするか）であって、停止後の完全な台帳ではありません。

== steamId について（client-reported, consistency-checked）==

このフィールドはサーバーが自力で算出した値ではなく、プレイヤーのクライアントが
報告し、サーバーが整合性チェックをして残した値です。エンジンにはサーバー側で
正確な Steam64 を取る道がありません：サーバーが取れるのは Java long が Lua 変換で
浮動小数点化された値で、Steam64 は約 7.66e16、この桁の浮動小数点精度は 16——
末尾 1-2 桁が黙って落ちます。SteamID を文字列化するエンジン関数はすべて
クライアント限定です。

サーバーのチェックは 2 段：形式（17 桁、Steam 個人アカウント帯の下限以上）と、
報告値をサーバー自身の浮動小数点値と突き合わせる整合性検査。でたらめは弾かれ
ますが、同一の浮動小数点値に対応する隣接 Steam64 は 15-16 個あり、その多くは
実在アカウントなので、悪意あるクライアントがその中の 1 つで検査を通す可能性は
残ります。

したがって：人間が読む対照表・監査記録・改名をまたぐ追跡には使えます；
権限付与・BAN・所有権判定には**使ってはいけません**。権威値が必要なら停止後に
セーブの players.db の networkPlayers テーブルを読んでください。あちらの steamid
はサーバー自身が書いた文字列カラムです。

== 外部ツールを書く人はこれを守ってください ==

  1. ファイル全体を厳格な JSON として解析。失敗したらファイル不存在と同様に扱い、
     破壊的操作を中止——外側オブジェクトはファイル末尾で閉じるので、途中で
     切れたファイルは厳格解析を通りません。行単位のストリーム読みはしないこと。
  2. players の件数は count と、online:true の件数は online と一致すること。
     重複排除キーは (name, idx)；重複が出たら文書全体を破棄、黙った重複排除禁止。
  3. 鮮度は fail-closed：now - ts が interval の数倍（推奨 3 倍）を超えたら出力は
     停止済みとみなす（サンドボックス無効化、MOD 削除、サーバー停止、または MOD
     の書き出し拒否）。ts が現在より新しい（時計ずれ約 60 秒超）場合も中止——
     未来のタイムスタンプは古いファイルを永遠に新鮮に見せます。interval が
     1-300 の範囲外＝信頼不可。
  4. save は操作対象のセーブディレクトリ名と一致すること；offlineAuthority は
     "observed-subset" であること。
  5. オフラインリストで反証しない（前節参照）。offlineSince が新しい、または
     offlineTruncated が true の場合、オフライン履歴はさらに不完全——破壊的
     操作はより保守的に。
  6. ファイル不存在は許容（機能は既定オフ、または有効化直後で最初の周期前）。

== プライバシー ==

「プレイヤー座標ファイルの出力」を有効にすることは、プレイヤー座標をディスクに
書くことを意味します。外部ツールと組み合わせるときだけ有効にしてください；
一般のサーバーには不要です。
